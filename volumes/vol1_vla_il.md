**使用方式**：题目默认折叠，先自己答一遍主问，再点开对照；然后**合上，从主问开始把整条追问链讲一遍**——本卷练的是"扛得住往下钻"，不是名词解释。追问链 3-5 层是实录里的真实下钻深度。

**本卷追问模式**（来自调研结论，面试官在 VLA 方向的固定下钻手法）：
1. **数字怎么定的**：chunk size、插值窗口 N、推理步数、显存——答上概念必被追问数值依据
2. **给症状、定根因**：复现慢/抖动、真机成功率低、训练 loss 降但效果差，几乎每场必出一道
3. **训练侧↔部署侧跨层**：任何训练问题最终被拉回"真机上跑起来会怎样"
4. **方案→备择对比**：为什么不用 X（现成库 / 另一种 action head）
5. **诚实边界**：没做过的层直说"没做过+怎么排查"，比编造安全

<summary><span class="lv lv-l1">L1</span> <span class="freq">🔥×3</span> <b>C01</b> · VLA 的输入和输出分别是什么？</summary>

**答**：VLA（Vision-Language-Action）= 在视觉-语言模型上接动作输出，让模型直接生成机器人动作。**输入**：一个或多个相机图像（外部 + 腕部）+ 语言指令 + 机器人本体状态（关节角、夹爪开度、末端位姿）。**输出**：未来一段动作序列（action chunk）——连续轨迹点，或离散化后的动作 token。推理频率通常 3-10Hz，靠 chunk + 低层插值对接 50-500Hz 的实时控制。

**追问 1**：为什么机器人领域需要 VLA，而不是传统控制算法？
**答**：传统"感知-规划-控制"管线要为每个任务手工设计抓取点、状态机、技能原语，换任务就要重新建模。VLA 把互联网级视觉-语言预训练迁移过来：同一个模型服从多样语言指令、泛化到训练时没见过的物体和场景，任务描述从"代码"变成"话"。

**追问 2**：VLA 解决的核心问题是什么？
**答**：打通"语义理解 → 动作输出"。VLM 知道"杯子"是什么，但输出不了关节力矩；VLA 的贡献是把动作变成模型可生成的表示（token 或连续分布），并用大规模机器人数据把语义空间和动作空间对齐——本质是数据稀缺领域借预训练换泛化。

**深挖**：VLA 现在的局限？（高频控制、精度、实时性、数据成本——引出 C08/C12）

**易错**：把 VLA 说成"视觉+语言+动作三个网络拼起来"，说不出它与普通多模态模型的本质区别——区别就在动作的**输出表示**（token 化 or 连续生成头）。

<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C02</b> · VLA 的 action head 有哪些常见设计？</summary>

**答**：①**离散 token 自回归**（RT-2 / OpenVLA）：连续动作按维度分桶转 token，当词表生成——最大程度复用 LLM，但推理逐 token 慢、离散化有精度损失；②**回归头**：MLP 直接回归动作向量，最简单，但多解任务会塌到均值；③**CVAE + chunk**（ACT）：latent 变量建模拟合多模态，一次前向出整段 chunk，快；④**Diffusion**（Diffusion Policy / RDT）：从噪声多步去噪，多模态表达最强，采样步数多；⑤**Flow Matching**（π0 / π0.6）：学速度场，少步 ODE 积分，连续动作里延迟最低档。

**追问 1**：π0、π0.5、π0.6 分别是什么？代码上什么区别？
**答**：π0：PaliGemma 3B VLM + flow matching 动作专家，输出连续 chunk。π0.5：加**高层子任务生成**——VLM 先自回归输出语义子目标文本，再生成动作，两阶段推理；训练引入 web 数据与更强跨机器人共训，主打开放世界泛化。π0.6：主攻**后训练**——用带修正的经验做 RL（experience & corrections），推理时自适应集成多个动作 chunk，真机长程任务成功率显著提升。代码差异集中在：高层头与两阶段推理循环、RL 后训练管线、ensemble 推理逻辑。

**追问 2**：讲一下 flow matching 的原理。
**答**：把数据 $x_0$ 和噪声 $\epsilon$ 沿直线路径插值：$x_t = (1-t)x_0 + t\epsilon$。网络学该路径上的恒定速度场 $v_\theta(x_t, t) \approx \epsilon - x_0$，损失为 MSE。推理时从纯噪声出发，用 Euler 积分沿速度场走几步到数据侧——比 diffusion 的随机游走采样步数少、路径直。

**易错**：把 π0 说成 diffusion 模型。它是 flow matching——训练目标（速度场 vs 噪声预测）、路径（直线 vs 弯曲）、采样（确定性 ODE vs 随机链）都不同。

<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C03</b> · 讲一下 π0 的整体架构？</summary>

**答**：π0 = **PaliGemma（3B VLM：SigLIP 视觉编码器 + Gemma 语言模型）+ 动作专家（约 3 亿参数的小 transformer）**。图像 token、语言 token、本体状态与带噪声的动作 token 拼进同一序列做联合 attention——动作 token 的更新走动作专家的独立权重，其余走 VLM。输出侧用 flow matching 生成整段 action chunk（如 50 步、50Hz）。预训练用大规模多机器人数据（官方口径 1 万小时级、7 种机器人配置）与多模态网络数据共训，微调后在 LIBERO 基准平均成功率 96%+。

**追问 1**：预训练数据大概什么构成、量级多少？
**答**：多机器人真机操作（dexterous 为主）+ OXE 等公开集 + 图文网络数据防语义遗忘。量级按官方博客口径 1 万小时级；面试能说出"真机为主、网络数据防遗忘、多配置混合"即可，数字说错比说不出更减分。

**追问 2**：3.3B 参数推理要多少显存？怎么估的？
**答**：权重 fp16 约 2×3.3B ≈ 6.6GB，加 KV cache 与激活，峰值 8-10GB 量级——8GB 卡勉强、16GB 从容。训练另算：AdamW 优化器状态再加约 12B 字节级（2×fp32 动量 + fp32 主权重），全参微调要 A100 级。估法："参数量 × 每参数字节数，逐项加"。

**追问 3**：action chunk 有什么优缺点？
**答**：优点：时间一致建模，动作平滑，抗单帧观测噪声。缺点：响应慢（观测变化要等下一次推理）、chunk 后段用的是**过期观测**（stale observation）。缓解见 C08（RTC / temporal ensembling）。

**易错**：把动作专家说成"接在 VLM 后面的另一个模型"——它是同序列联合 attention 里的独立权重块，不是级联网络。

<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C04</b> · π0.5 的分层推理是怎么回事？开放世界泛化靠什么？</summary>

**答**：π0.5 把推理拆成两层：**上层** VLM 自回归生成语义子任务文本（"打开抽屉 → 抓住杯子 → 放入"）；**下层** flow matching 动作专家按当前子任务生成连续动作。训练时用带高层标注的数据 + web 数据 + 多机器人数据共训。开放世界泛化的来源：语义层的预训练知识 + 子任务分解把长程任务切成短程可执行段——在陌生家庭环境（新厨房布局、新物体）也能执行，这是 π0.5 相对 π0 的核心卖点。

**追问 1**（场景题）：把一台新机器人（7 维动作：6 关节 + 1 夹爪，1 个外部相机 + 1 个腕部相机）接入 π0.5 微调，怎么做？
**答**：①定义新 action 向量（7 维）与本体状态表示，**算新 norm 统计**（均值方差从新数据来）；②相机内外参标定 + 与控制频率的时间同步；③VLM 主干冻结或 LoRA，**重训/微调动作专家**适配新动作维度与双相机输入布局；④几百到几千条遥操作演示起步，输入按 π0.5 的 prompt 模板拼装；⑤小任务集闭环评测再扩。接口对齐先于训练。

**追问 2**：为什么不能直接拿预训练权重 zero-shot 用？
**答**：动作空间、相机布局、本体动力学都是新的——预训练只给语义与操作先验，接口层（action 映射、观测归一化）必须用新数据重对齐。

**易错**：场景题里忘了 norm stats 和相机标定——"接得上"和"训得好"是两件事，面试官在等你说出"统计量重算"这一步。

<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×4</span> <b>C05</b> · RT-2/OpenVLA 自回归、π0/RDT 流匹配、ACT/CVAE——怎么取舍？</summary>

**答**：按四个轴比较：**推理延迟**：自回归逐 token 最慢（几十 token 串行）；CVAE 一次前向最快；流匹配/diffusion 介于中间，步数可换延迟。**多模态分布**：diffusion/flow 最强，CVAE 靠 latent 瓶颈居中，回归头会均值塌陷，离散 token 视桶数。**精度**：连续生成 > 离散 token（桶宽=分辨率下限）。**语义能力**：自回归与 LLM 联合最顺。**选型**：高频精细操作 → 连续生成头（flow/diffusion）+ chunk；重语义、长程任务 → VLM 自回归或分层（π0.5 式）；算力极紧 → ACT。RDT 是统一动作空间上的 diffusion transformer，思路是"一个动作空间适配多本体"。

**追问 1**：为什么扩散/流模型适合机器人动作，而回归头不行？
**答**：同一任务往往有多条可行轨迹（从左从右抓都行）——动作分布天然**多模态**。回归头对多模态目标拟合出条件均值，落在两条轨迹之间（不可执行）；生成式模型从噪声分布采样，能落在某一条真实轨迹上。

**追问 2**：那离散 token 的精度损失怎么量化？
**答**：256 桶时每维分辨率 ≈ 动作范围的 1/256（0.4%），对关节角通常够、对高精度装配不够；而且 token 间独立离散化会放大累积误差——连续头没有这一层量化噪声。

**易错**：背得出每个模型的创新点，却说不出"同一框架下的 trade-off"——TL 面要的就是横向比较表，建议按上面四个轴自己画一遍。

<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C06</b> · ACT 的训练和推理流程？chunk size 怎么选？</summary>

**答**：ACT = CVAE + transformer chunk 解码器。**训练**：CVAE encoder 把未来 L 步真值动作 + 当前观测压缩成 latent z（高斯），decoder 以 z + 观测为条件，transformer 自回归式输出整段 chunk；损失 = 动作 L1 + KL(z‖N(0,1)) +（可选）图像重建。**推理**：没有 encoder——z 取先验均值，一次前向出整段 chunk，无迭代采样，实时性最好。

**追问 1**：chunk size 怎么选？
**答**：按任务时间尺度：快速反应任务短（10-20），精细慢动作长（50-100）。约束是"chunk 至少覆盖推理周期×安全余量"（3Hz 推理 → chunk ≥ 0.33s 的动作）再叠平滑需求，实验扫。长 chunk 平滑但 stale observation 严重。

**追问 2**：CVAE 会不会 posterior collapse？怎么处理？
**答**：会——KL 项把 z 压向先验，decoder 学会忽略 z，退化为单模态 BC。处理：调 KL 权重退火、z 温度、encoder 预训练；判断方法是看 KL 项是否塌到 0 和 latent 对输出的敏感度。

**追问 3**：和普通 BC 的区别？
**答**：BC 单步回归、单模态、误差逐步累积；ACT 用 chunk（时间一致）+ latent（多模态）+ 全段 L1（抗累积）三件事同时缓解。

**易错**：说推理时也要跑 encoder——推理只有 decoder，z 来自先验。

**实录**：[牛客·VLA算法实习面经](https://www.nowcoder.com/feed/main/detail/a17ad61fa5d6433881915334973f5354)（ACT 流程实录）、CSDN《TL常用算法面经（四）》（[链接](https://blog.csdn.net/lovely_yoshino/article/details/160743611)，模拟追问链）

<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C07</b> · 为什么说 flow matching 的 diversity 表达不足，Diffusion Policy 就是多样？</summary>

**答**：这是一道**有争议的拷打题**，先给论点再给辨析。**拷打方的论点**：DP 从随机噪声出发、多步**随机**去噪，天然覆盖多模态；FM 是直线路径 + 固定速度场，工程上常配**少步确定性 Euler**，输出偏保守。**更准确的辨析**：两者的初始噪声都是随机的——FM 多步采样同样能覆盖多模态；数学上 FM 可视为 diffusion 沿直线路径的特例（速度场 = 得分函数的等价形式），分布表达本无高下。实践中的"FM 不多样"多来自：步数压太少、温度/噪声调度没调、数据本身窄。

**追问 1**：DDPM 和 DDIM 的区别？
**答**：DDPM 每步采样带随机噪声，必须走满步数；DDIM 是确定性 ODE 式采样，同均值不同方差，可以跳步大幅加速——生成轨迹固定（同噪声同结果）。机器人部署里要"稳定可复现"用 DDIM 式，要"探索多样"用随机链。

**追问 2**：训练目标上两者差在哪？
**答**：diffusion 学噪声/得分（多步、弯曲路径）；FM 学直线速度场 $\epsilon - x_0$（一步回归即得，曲线路径的 CFM 变体除外）。FM 训练更稳、更简单，这是它被 π0 选中做 action head 的原因之一。

**易错**：跟着题目断言"FM 就是不多样"——把初始噪声的随机性丢了。正确的答法是先接住论点、再指出它混淆了"模型表达"和"工程配置"。

**实录**：CSDN《为什么说flow matching diversity表达不足…》（[链接](https://blog.csdn.net/weixin_43332715/article/details/148759368)，技术博客）、CSDN《从ROS通信到生成模型》（[链接](https://blog.csdn.net/m0_51738372/article/details/160307298)）

<details class="chain">
<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×4</span> <b>C08</b> · VLA 推理只有 3Hz，机械臂需要 50Hz 控制频率，怎么办？</summary>

**答**：分层解耦。VLA 出的是**稀疏目标轨迹**（3Hz waypoint 序列），低层控制器以 50Hz 做轨迹插值（线性/样条 + 低通滤波）跟踪执行。要让"新推理"无缝接进来而不是等 chunk 走完，有三档方案：①**chunk 内插值**：最简单，chunk 边界会有速度突变；②**Temporal ensembling**（ACT）：每个控制周期都重新推理，对重叠时间段的多个预测做指数加权平均——平滑但算力 ×N；③**RTC**（π0 团队）：推理新 chunk 时沿时间轴与**正在执行**的动作对齐（把未执行部分的旧动作当作冻结/调度目标），新旧融合，无算力爆炸也不需要重训。

**追问 1**：预测动作执行时机械臂抖动，怎么排查？
**答**：按出现位置分：chunk **边界处**抖 → 边界不连续，上 RTC/ensemble；**全程**高频抖 → 插值/滤波参数问题或推理数值噪声；**特定观测下**抖 → norm 统计错或数据里混入脏动作。先定位"什么时候抖"再定根因。

**追问 2**：RTC 具体怎么实现？
**答**：推理时把新 chunk 的每个动作点映射到"绝对执行时刻"，与正在执行轨迹的未来部分在重叠区间做对齐融合（可冻结已承诺动作、只改未执行段）；π0 团队报告其在推理频率 ×chunk 长度错配场景下显著优于 ensembling。〔实录到此为止，实现细节属推断〕

**追问 3**：提速有什么办法？
**答**：少步 flow/DDIM、模型量化、视觉 token 剪枝、异步推理（感知与动作解耦流水线）、小模型蒸馏。

**追问 4**：桌面高度是固定的吗？深度敏感任务要加什么？
**答**：不固定——纯 RGB VLA 对桌面高度/物体位姿的微小变化有鲁棒性上限；插入类深度敏感任务要加腕部视觉伺服、精定位模块或深度输入兜底。这一问考"知道模型的部署假设"。

**易错**：只答"插值"——面试官在等 chunk 边界不连续这个根因和 RTC/ensembling 的对比，答插值只拿第一层的分。

**实录**：[牛客·VLA面经分享](https://www.nowcoder.com/feed/main/detail/7b8f541c9bef4733a0f738d0628b1f65)（3Hz/50Hz、抖动原题）、[牛客·VLA算法实习](https://www.nowcoder.com/feed/main/detail/a17ad61fa5d6433881915334973f5354)（RTC 实现追问）、[牛客·云鲸](https://www.nowcoder.com/feed/main/detail/b18ddc5475694fc0bcedc07f9764d10d)（RTC 参数）、GitHub [offerseed #6](https://github.com/offerseed/interview-experience/issues/6)（ensemble vs RTC 选型）
</details>

<details class="chain">
<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C09</b> · OpenVLA 怎么微调？迁移到你自己的机械臂第一步改什么？</summary>

**答**：OpenVLA = 7B（Llama2 骨干 + DINOv2/SigLIP 双视觉编码器），动作 7 维分桶成离散 token。**微调**：LoRA/QLoRA 冻结主干只训低秩增量，单张 A100/4090 可行；全参需要多卡。**数据**：几百条遥操作演示起步 + 覆盖失败恢复的数据；质量优先于数量。**迁移第一步不是训练，是接口对齐**：①动作空间（维度/单位/顺序）与 OpenVLA 的 token 化约定对齐，重算归一化统计；②相机内外参、分辨率、安装位对齐；③本体状态表示对齐。然后才是 LoRA 微调 + 真机闭环。

**追问 1**：动作空间不匹配怎么办？
**答**：维度不同 → 重定义 token 化映射（分桶方案/反离散化公式）并重训动作头侧；自由度不同但语义相同（如末端位姿 vs 关节角）→ 换算或改输出表示；差太大就别硬迁——换动作头。

**追问 2**：OpenVLA 适合高频控制吗？
**答**：不适合——自回归 7B 一次推理 1-5Hz。高频要靠低层控制器 + 插值兜底（见 C08/C12），这也是"VLA 只当慢回路"论点的由来。

**易错**：把迁移答成"继续预训练"——接口没对齐，训了也白训；norm 统计和相机标定是第一刀。

**实录**：CSDN《具身智能VLA面经总结（小鸡毛版）》（LoRA/PEFT 类）、CSDN《TL常用算法面经》系列（迁移追问，整理）
</details>

<details class="chain">
<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C10</b> · 训练一个新任务/新机器人的完整流程是什么？怎么评估？</summary>

**答**：流程：①任务定义与**成功判据**（可自动判定）；②数据采集——遥操作演示 + 失败与恢复数据，覆盖目标物体/位姿/干扰的分布；③训练（微调为主）；④离线评测——动作误差、chunk 一致性；⑤真机评测——成功率为主指标；⑥失败分析 → 补数据/调结构 → 迭代。**评测协议**：每任务 ≥20-50 trials、随机化初始状态与物体位姿、固定随机种子记录、成功判定自动化（视觉或状态阈值）——这几个数字面试必追。

**追问 1**：评估具身模型，只看 Perplexity 够吗？
**答**：不够——PPL 是语言/预测指标，与动作质量不相关。具身看：任务成功率（主）、跨扰动泛化（光照/位姿/干扰物）、延迟与实时性、失败模式分布。语言侧指标只能当训练健康度信号。

**追问 2**：离线动作误差很低，能说明真机成功率高吗？
**答**：不能直接划等号——离线误差是观测分布内的拟合，真机隔着执行动力学（延迟、摩擦）与分布漂移。两者背离时的排查见 C11。

**易错**：评测协议说不出数字（多少 trials、怎么随机化）——"测过了"和"测得可信"是两回事。

**实录**：CSDN《具身智能VLA面经总结（小鸡毛版）》（训练与评测类）、[gankinterview 具身智能面试考点](https://www.gankinterview.cn/blog/embodied-ai-interview-when-large-models-are-integrated-into-robots-what-new-know)（Perplexity 原题）
</details>

<details class="chain">
<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C11</b> · 训练损失持续下降、离线动作误差不高，但真机成功率始终很低，优先检查哪些环节？</summary>

**答**：这是"指标背离"排障题，按信息增益排序：①**分布差**——真机观测（曝光、视角、遮挡、桌面变化）与训练数据统计不一致，先把真机 rollout 的观测可视化对比训练集；②**执行差**——控制频率、通信延迟、插值方式与离线假设不符，chunk 边界抖动见 C08；③**协议差**——成功判定、初始状态随机化是否和数据采集口径一致；④**数据覆盖**——失败模式根本不在演示分布里。顺序：先看观测对不对齐（最便宜），再查执行链路，最后才怀疑模型。

**追问 1**：VLA 策略任务没做成，怎么系统 debug？
**答**：五层从感知往下拆：视觉输入（曝光/遮挡/相机位姿）→ 语言理解（指令是否在训练分布）→ 状态对齐（时间同步、坐标系）→ 动作头（输出平滑度、norm）→ 数据覆盖（失败模式有无演示）。每层给一个 5 分钟可验证的检查。

**追问 2**：前向反向都能跑，第一次 optimizer.step() 显存溢出，怎么定位？
**答**：Adam(W) 的状态（动量×2，fp32）与 fp32 主权重在**第一次 step 时才分配**——峰值滞后于前向。定位：打印参数量 × 优化器状态的字节估算；处理：梯度检查点、减 batch/序列长、8-bit 优化器、混合精度 offload。

**易错**：OOM 就怪"模型太大"——很多是优化器状态 + 激活峰值的时间点问题，说得出"为什么第一次 step 才爆"才是懂显存。

**实录**：GitHub [offerseed #6](https://github.com/offerseed/interview-experience/issues/6)（指标背离、OOM 原题）、CSDN《具身智能TL常用算法面经》（debug 五层，整理）
</details>

<details class="chain">
<summary><span class="lv lv-l3">L3</span> <span class="freq">🔥×2</span> <b>C12</b> · 预训练模型低频输出和底层高频控制怎么协同？插值窗口的大小怎么确定？</summary>

**答**：分层回答。VLA 低频输出的是**带时间参数化的连续轨迹段**，低层控制器把它当作连续时间轨迹做 50Hz 插值执行（样条/线性 + 滤波）。**"插值轨迹 vs 离散 waypoint 拟合"的本质差异**（实录里面试官用复述确认法问）：插值保持整段轨迹的连续语义——新观测到达时在轨迹级融合；对孤立 waypoint 做回归则丢掉时间结构，扰动下要么滞后要么过冲。**协同结构**：预训练模型是慢回路（语义级目标，3-10Hz），实时控制器是快回路（稳定执行，50-500Hz），两层用 RTC/ensemble 接口解耦（见 C08）。

**追问 1**：均值窗口的大小是怎么确定的？
**答**：不能拍脑袋——由端到端延迟（推理+通信）、任务频率、抖动抑制需求共同定，实验扫窗口对"真机成功率 + 动作抖动能量"两个指标的影响，选拐点。答"实验定的 + 给出指标"就是这层的满分结构。

**追问 2**：窗口太大/太小会怎样？
**答**：太大 → 动作滞后、响应钝，来不及纠偏；太小 → 平滑不足、噪声直通。

**易错**：这题的实录里面试官会**先复述你的话**（"是不是说这是一种轨迹插值…"）再要本质差异——确认式追问，考你是否真理解而不是背词。被复述时不要慌着点头，把差异讲透。

**实录**：GitHub [Cgxiaoxin 面试复盘·浙江滴石](https://github.com/Cgxiaoxin/Embodied_Learning/blob/main/interview/%E9%9D%A2%E8%AF%95%E5%A4%8D%E7%9B%98.md)（确认式追问全记录）
</details>

<details class="chain">
<summary><span class="lv lv-l3">L3</span> <span class="freq">🔥×1</span> <b>C13</b> · UniVLA 这类潜在动作架构怎么搭？你在其中承担哪些工作？</summary>

**答**：UniVLA 思路：用 **latent action model（VQ-VAE 式）** 把跨机器人视频里的动作离散成潜在动作 token——不绑定具体本体；VLM 在"语言 + 潜在动作"上做自回归训练；部署时 decoder 把潜在动作映射回具体机器人的连续动作。**subtask 标注**：按片段起止时间划分（规则+人工校验）；**prompt**：拆解后的子任务文本随观测一起给；**规模**：主干 7B 级、latent 模块 1-2B 级（面经追问口径）。

**追问 1**：late action model / VQ-VAE 部分的逻辑？
**答**：编码器把连续动作段量化到 codebook（离散潜在动作），训练用重构损失 + codebook commitment loss；好处是跨本体共享"动作词汇"、可与语言 token 同一序列训练。

**追问 2**：架构这么大，你承担哪些工作？（真实性核验）
**答**：如实划边界：做了数据管线/某个模块的微调/评测，就说具体的；没碰过预训练就直说"预训练不是做的，我的部分是…"。这题挂人的不是不会，是装会。

**易错**：被追问"数据量多大/谁标的/latent 几个 code"时含糊——这层追问就是真实性测试（参考卷五）。

**实录**：[牛客·傅利叶一面](https://www.nowcoder.com/feed/main/detail/37af3ac1986b438c81cd26ab90a792a8)（四层深挖全记录）〔本链部分实现细节为推断，已标注〕
</details>

<details class="chain">
<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×1</span> <b>C14</b> · 项目里的点云主要用在什么场景？如何看待点云在 VLA 中的作用？</summary>

**答**：VLA 主流是 RGB 输入——与互联网图文预训练分布对齐、信息密度高、部署便宜。点云/深度在三类场景有不可替代性：精确抓取位姿估计、深度敏感任务（插孔、装配）、无纹理/透明物体的几何兜底。**观点**：短期"RGB + 腕部相机"覆盖大多数操作任务，精细操作加深度作辅助模态；全点云端到端与预训练生态不兼容，是成本问题不是能力问题。

**追问 1**：你的 VLA 方案里为什么没用点云？（项目型追问）
**答**：答真实原因（任务对深度不敏感/腕相机已覆盖/预训练权重吃 RGB），再主动补"什么情况下我会加"——把回答落在决策依据上而不是站队。

**易错**：绝对化站队（"点云没用"/"必须点云"）——这题考的是你知道两种模态各自的适用边界。

**实录**：[牛客·具身算法一面](https://www.nowcoder.com/feed/main/detail/ece59d44599042c39696b3b1114bb3b4)

<details class="chain">
<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×2</span> <b>C15</b> · 端到端 VLA 要不要显式世界模型？VLA 和 world model 的区别？</summary>

**答**：**区别**：VLA 是反应式映射（观测+指令 → 动作），不显式建模环境动力学；world model 学"状态+动作 → 下一状态"的预测器，能想象、规划、评估动作后果。**要不要**：两派——规模派认为端到端数据规模会隐式吸收动力学，不需要显式 WM；结构派认为 WM 提供三件 VLA 没有的东西：样本效率（合成经验做 RL 后训练）、长程规划（想象搜索）、安全预演（危险动作先在 WM 里试）。当下工程答案：VLA 出动作 + WM 做预演/数据增广的**分层组合**是活跃方向。

**追问 1**：VLA 有哪些改进方向？
**答**：动作表示（更好 token 化/连续头）、数据（跨本体、失败恢复、仿真合成）、后训练（RL + 修正，π0.6 路线）、推理（RTC、异步、蒸馏）、分层（VLM 规划 + 快动作头）。

**易错**：把 world model 说成"更高级的 VLA"——两者是互补组件（一个输出动作、一个预测结果），不是替代关系。

**实录**：CSDN《具身智能VLA面经总结（小鸡毛版）》（VLA与世界模型类）、知乎《2026 秋招仿真+强化学习控制岗》（语境）
</details>

<details class="chain">
<summary><span class="lv lv-l3">L3</span> <span class="freq">🔥×1</span> <b>C16</b> · Qwen-VL 的 chat template 里 VL 的特殊 token 有哪些？（引导式深挖链）</summary>

**答**：视觉前后有 **vision start / vision end** 包裹，中间是 image pad 占位 token（数量与图像 token 数一致），这是 VLM 把图像"塞进语言序列"的标准做法。ViT 侧 Qwen2-VL 用**动态分辨率 + window attention**（多数层窗口内 attention，少量全局层），训练稳、任意分辨率省算力。

**追问 1**：24×24 的图像怎么通过卷积得到 16×16 输出？（当场算）
**答**：通式 $(H - K + 2P)/S + 1$，代入 24→16：$24 - K + 2P = 16S - S$。一组可行参数：K=9, P=0, S=1（24-9+1=16）；或 K=5, P=1, S=2（(24-5+2)/2+1=12.5 不行）→ K=5,P=0,S=2 → 10.5 不行；正确一组：K=9,S=1。面试官要的是公式熟练 + 当场代数，不是背具体参数。

**追问 2**：VL 模型里最慢的部分在哪？怎么加速？
**答**：视觉 token 多（一张图几百 token），瓶颈在长序列 attention 和大线性层。加速：KV cache（缓存历史键值，增量解码）、FlashAttention（分块计算省 HBM 读写）、视觉 token 压缩/剪枝、量化。

**追问 3**：做过 SFT 吗？学习率多少、踩过什么坑？
**答**：量级 1e-5 上下（比预训练小一到两个数量级）；常见坑：视觉 token 掩码没对齐、normalize 漂移、lr 过大导致灾难性遗忘。如实讲自己的部分。

**易错**：这题是**引导式追问**的样本——面试官会顺着你的每个词往下带（帖主原话"面试官实力很强，会引导式提问"）。答不出当场推，比背错答案印象好。

**实录**：[牛客·千寻智能一面](https://www.nowcoder.com/feed/main/detail/fe79ba8a8d36464c96261292dcadccc4)〔卷积参数组为推断补全，公式为通用知识〕
</details>

<details class="chain">
<summary><span class="lv lv-l2">L2</span> <span class="freq">🔥×1</span> <b>C17</b>（低频备选）· 怎么让一个模型同时上人形、机械臂、四足？（cross-embodiment）</summary>

**答**：核心是**统一动作表示**：把不同本体的动作向量归一化到统一维度（缺失维度 mask 掉）、本体状态归一化、统一控制频率语义；数据层多本体共训（Open X-Embodiment、π0 的多配置、RDT 的统一空间）；新本体接入 = 冻结语义主干 + 适配动作映射（见 C04 场景题）。难点在动作语义不对齐（末端位姿 vs 关节空间）和数据配比。

**易错**：只答"数据混起来训"——mask 与归一化的接口设计才是面试官要的。

**实录**：[techinterview.net Physical Intelligence 指南](https://www.techinterview.net/blog/physical-intelligence-pi-interview-guide)（英文 prep 站，无实录追问链，降权收录）
</details>
